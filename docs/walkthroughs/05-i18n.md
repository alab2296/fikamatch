# 05 - Translations and translated errors

**What changed:** every error the API sends back now has a stable `code` and a message in the user's language.

1. Message files live in `src/i18n/messages/sv.json` and `en.json`. A test checks both have the same keys.
2. `detectLocale()` reads the `Accept-Language` header, respects the `q=` weights, and falls back to Swedish.
3. Each request gets `req.locale`. The 404 and error handlers in `src/app.ts` use it to build `{ code, message }`.
4. Unexpected errors return a generic message, never the internal details (they are only logged).
5. Throw `new ApiError(403, "forbidden")` in a route to send a translated error with that status.

**Why:** Swedish comes first and all user-facing text must come from translation files, not from code.
